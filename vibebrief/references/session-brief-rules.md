# Session Brief Rules

Session Brief is the default mode when a user wants to understand one AI coding session.

Keep the brief short, plain, and useful for the next decision. It should usually explain the session goal, what the AI says it changed, what remains unconfirmed, and the next practical step.

Do not invent validation. If the input does not include a command result, test output, screenshot, log, or user confirmation, treat the result as unconfirmed.

Write for a smart non-engineer. Avoid jargon when a simple phrase works.
